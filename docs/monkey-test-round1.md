# 游戏随机测试与修复记录

日期：2026-10-25

## 测试结果

- 25 组自动化测试全部通过。
- 4 个固定种子，各执行 1,000 次随机菜单、点击与键盘操作，共 4,000 次；检查监听器泄漏和存档数据范围。
- 几何、数学模式分别测试普通与开发者状态，各模拟 1,000 帧，共 4,000 帧；随机移动、切出窗口、拾取金币与资源、选择升级并重开，检查数值合法性和开发者属性。
- 浏览器中执行 48 次随机点击，覆盖说明、换肤、错题本、音效、两类游戏及数学普通/特殊模式的往返。
- 覆盖全部 32 种成就组合，检查鸡蛇只在集齐后出现及定时消失。
- 类型检查与差异空白检查通过。

## 已修复

1. 返回主页再开始时，旧升级弹窗及暂停状态残留。
2. 死亡后开始新游戏，旧游戏结束弹窗残留。
3. 重开游戏未清除攻速加成。
4. 特殊数学模式重开后变为普通规则。
5. 数学答案使用宽松整数解析，包含字母的小数/混合输入可能被当作整数处理；现在只接受安全范围内的完整整数。
6. 拾取资源触发升级后，同一帧敌人仍可造成伤害甚至杀死玩家。
7. 已过期子弹在移除前仍能命中。
8. 已过期金币和晶核仍能被拾取。
9. BOSS召唤怪未遵守原始速度200%的上限。
10. 怪物倍率达到100倍后，存活怪物仍持续强化；现在按实际倍率增量强化，同时保持BOSS固定攻击规则。
11. 切出窗口时丢失松键事件，角色可能持续移动；现在失焦清除移动按键。
12. 金币处于最大安全整数边界再拾取，可能写入下次加载不认可的数值；现在保持安全整数上限。

另调整：错题本在重开和返回主页后保留，由“清空错题本”按钮明确清除；死亡当帧停止处理后续敌人攻击。

## 保留的回归检查

100%暴击概率后每次增加5个百分点伤害、残血反杀的血量和怪物阶数边界、重复换肤不透支、重置后只保留重新开始成就、坏存档降级处理、成就定时器和键盘监听器清理。

测试入口：项目内 `pnpm test:monkey`，需要兼容项目的 Node 版本（Next.js 16要求 Node 20.9及以上）。

## 范围与限制

自动化随机操作与游戏帧测试运行真实项目源码，但使用内存存档与模拟 React hooks/Canvas，不等同于完整浏览器引擎压力测试；浏览器检查另行执行。测试不修改 localhost 页面已有金币、皮肤与成就；浏览器验证使用 127.0.0.1 的独立来源。没有进行整夜运行、移动设备触控或生产构建验证，因此不能承诺消除所有潜在问题。
